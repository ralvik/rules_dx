# `dx docs`

Implementation status: delivered.

```text
dx docs [--check] [--serve [--port <n>]] [--here] [scope ...]
```

`dx docs` builds the [unified documentation
site](../../documentation/site.md) from versioned
[documentation IR](../../documentation/doc-ir.md) generated by Bazel extraction actions,
plus authored prose. IR is cached by Bazel like lint results or generated code; it is
not committed or written alongside source files.
With no scope it selects the repository docs site (`//docs/site:demo_site`,
`//docs/site:demo_aggregate` in `--check`); scope follows the same
label/pattern/path resolution as the other workflow commands. The build
itself is non-mutating: it writes only to Bazel outputs, never to sources.

`--check` performs extraction and validation without rendering HTML. Normal build performs
the same validation and then renders; both fail on unresolved cross-links and missing API
references. Both select the shared Bazel extraction/aggregation graph, not separate checker
implementations. Check mode does not compare IR against committed snapshots or previous cache contents, and a
cache miss is not a check failure. It is not `mdbook test`, whose upstream contract tests Rust
examples rather than general site correctness. CI must exercise a full build for renderer evidence.
Non-mutating means
no source-tree writes; Bazel output and cache writes are permitted in both modes.
Rendered HTML is also a build artifact, never committed.

`--serve` builds once and previews the output locally for authoring (default port
8000). It
performs no caching of its own and is outside the Bazel action graph; the
served bytes are exactly the last build outputs.

Machine output follows the complete [Output
Protocol](../output-protocol.md). Failures name the affected (language,
package) unit and, on extractor drift, the pinned input whose schema
changed.
